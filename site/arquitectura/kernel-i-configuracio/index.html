    Kernel i configuració¶

    Aquest document descriu el nucli Symfony de l'aplicació: el kernel, els bundles, l'estructura de configuració, el contenedor de serveis, les variables d'entorn (12-Factor), les connexions Doctrine i els entorns.

    Com regenerar aquesta pàgina: les dades es poden contrastar en qualsevol moment amb bin/console debug:router (rutes), bin/console debug:firewall (firewall), bin/console debug:config doctrine/messenger/framework (paràmetres) i la lectura de config/ i src/.

    El kernel¶

    • Classe del kernel: App\Kernel (generat amb el maker, sense modificacions: carrega config/bundles.php, config/packages/ i config/services.yaml).
    • Punt d'entrada web: web/index.php — utilitza Symfony Runtime (require vendor/autoload_runtime.php) que selecciona automàticament el kernel segons el directori de treball.
    • Directori web públic: web/ (no public/). Està declarat a composer.json ("public-dir": "web"). Conseqüències:
    • El script de test bin/phpunit i el server:run de Symfony apunten a web/index.php.
    • Els assets compilats (AssetMapper/Tailwind) s'escrivien a web/assets_build/.
    • public/ conté només el holding.html (pàgina de manteniment estàtica).
    • Comandes de CLI: bin/console (mateix runtime, context CLI).

    Bundles (config/bundles.php)¶

    18 bundles registrats:

    Bundle Entorns Funció a Registrals
    FrameworkBundle tots Nucli: sessions, cache, router, templating, asset-mapper, messenger, workflows, mailer.
    DoctrineBundle + DoctrineMigrationsBundle tots ORM + migracions versionades (2 connexions: default i audit).
    SecurityBundle tots Tallafoc main, providers, voters, remember-me (vegeu Tallafoc).
    TwigBundle + TwigExtraBundle tots Plantilles (102 fitxers) + extensió de dates/urls.
    MonologBundle tots Logs per entorn (dev/test: var/log/* + handler d'errors; prod: json + when).
    DebugBundle dev Debug bar i dump.
    WebProfilerBundle dev, test Web profiler (guarat per ProfilerAccessGuardSubscriber).
    MakerBundle dev Generació de codi (make:entity, etc.).
    StimulusBundle + TurboBundle tots SymfonyUX: Turbo (mexes de formularis, frames) i Stimulus (controllers JS a assets/ i assets/ → web/assets_build).
    SymfonycastsTailwindBundle tots Comanda assets:tailwind (dev: watch, prod: build minificat).
    FlysystemBundle tots Custòdia privada de documents (vegeu Custòdia d'arxius).

    No s'usen bundles externs de pagament, blockchain, signatura ni IA: totes les integracions són adaptadors propis (vegeu Visió general → Ports i adaptadors).

    Estructura del fitxer de configuració¶

    config/
├── bundles.php            # 18 bundles per entorn
├── routes.yaml            # routes de bundles (_profiler, _wdt, asset-mapper)
└── packages/
    ├── framework.yaml     # secret, sessions; test: mock_file sessions
    ├── security.yaml      # firewalls, rol hierarchy, access_control
    ├── doctrine.yaml      # 2 connexions + 2 entity managers
    ├── messenger.yaml     # 5 transports + routing de 3 missatgers
    ├── workflow.yaml      # màquina d'estats item_lifecycle
    ├── flysystem.yaml     # storage item_document.storage
    ├── mailer.yaml        # DSN + envelope sender
    ├── asset_mapper.yaml  # paths + missing_import_mode
    ├── routing.yaml       # default_uri; prod: strict_requirements
    └── twig.yaml          # file_name_pattern; test: strict_variables
services.yaml              # paràmetres + registre App\ + bindings explicits

    Contenedor de serveis (config/services.yaml)¶

    • _defaults: autowire i autoconfigure actius → qualsevol classe de src/ és un servei (id = nom complet de classe) sense configuració explícita.
    • App\: → resource: '../src/': importa totes les classes del projecte.
    • Paràmetres declarats (no canvien entre màquines):
    Paràmetre Valor Ús
    env(AI_ASSISTANCE_ENABLED) true Feature toggle de l'assistència IA (Qwen VL local).
    env(MAILER_FROM_ADDRESS) info@registrals.com Remitent dels correus transaccionals.
    env(MAILER_FROM_NAME) Registrals Nom del remitent.
    app.ai_assistance_enabled bool(AI_ASSISTANCE_ENABLED) Paràmetres tipats per a injecció fàcil.
    • Bindings globals (bind:): string $mailerFromAddress i string $mailerFromName s'injecten automàticament en qualsevol constructor que tingui aquests paràmetres.
    • Configuracions explícites (l'únic apartat que tronsa l'autowiring):
    Servei Argumentació Per què
    App\Service\Security\EmailOtpService $appSecret = %kernel.secret% Signatura HMAC dels còdigs OTP d'1 dígit.
    App\EventSubscriber\ProfilerAccessGuardSubscriber $profiler = @?profiler (opcional) Guàrdia d'accés al profiler; en entorns sense profiler, null.
    App\EventSubscriber\VisitTelemetrySubscriber $appSecret, $environment Signatura i marcatge de la telemetria de visites.
    App\Service\OAuth\GoogleOAuthService $clientId, $clientSecret Credencials OAuth2 de Google.
    Ports → adaptadors Aliasing d'interfície (vegeu a sota) Arquitectura hexagonal.
    • Alias d'interfície (ports) — el domini depèn de l'interfície; el contenedor resol l'adaptador:
    Interfície (port) Resol a (adaptador) Arguments (env)
    BlockchainAnchorInterface PolygonAnchorClient BLOCKCHAIN_RPC_URL, BLOCKCHAIN_CONTRACT_ADDRESS, BLOCKCHAIN_HOT_WALLET_PRIVATE_KEY (default buid), BLOCKCHAIN_NETWORK
    SignaturitTimestampInterface SignaturitClient SIGNATURIT_API_TOKEN (default buit → mode sandbox), SIGNATURIT_BASE_URL
    IdentityVerificationGatewayInterface NamirialOnboardingClient NAMIRIAL_ONBOARDING_BASE_URL, NAMIRIAL_ONBOARDING_API_KEY (default buit), NAMIRIAL_ONBOARDING_REQUEST_TYPE_ID (default buit), NAMIRIAL_ONBOARDING_WEBHOOK_SECRET (default buit)
    PaymentGatewayInterface StripeGatewayClient STRIPE_SECRET_KEY (default mock), STRIPE_WEBHOOK_SECRET (default mock), STRIPE_PRICE_PLUS (default), STRIPE_PRICE_UNLIMITED (default)
    PdfRendererService — CHROMIUM_BINARY_PATH (default buit → cerca en PATH)

    L'adaptador IA (SglangVisionClient) s'autowireja sense arguments explícits: llegir SGLANG_* directament de l'entorn mitjançant la seva fàbrica.

    Stripe STRIPE_WEBHOOK_SECRET whsec_registrals_mock Validació de firma del webhook.

    Regla 12-Factor: cap secret de producció no ha d'aparèixer a .env ni a cap fitxer commitat. A producció, les variables es proporcionen pel servidor/contenidor (ex. docker run -e DATABASE_URL=…).

    Doble connexió Doctrine (config/packages/doctrine.yaml)¶

    L'aplicació fa servir dues bases de dades MySQL (mateix servidor, dos esquemes):

    Connexió BDD (DEV) Entity manager Mapeig
    default (per defecte) registrals default App\Entity (18 entitats)
    audit registrals_audit audit App\Audit\Entity (1 entitat: UserActivityLog)

    Configuracions rellevants:

    • enable_lazy_ghost_objects: true → ghost objects per a relacions lazy (rendiment; vegeu Visió general).
    • naming_strategy: underscore_number_aware → convenció snake_case a les taules.
    • profiling_collect_backtrace = kernel.debug (només dev).
    • use_savepoints: true → transaccions anuïllables (savepoints) en ambdues connexions.
    • Entorn test: dbname_suffix: '_test%env(default::TEST_TOKEN)%' (ParaTest).
    • Entorn prod: proxy auto-generació desactivada + cache de consulta/resultat a pools Symfony (doctrine.result_cache_pool, doctrine.system_cache_pool → cache.app / cache.system).

    Asset pipeline (AssetMapper + Tailwind)¶

    • config/packages/asset_mapper.yaml:
    • paths: [assets/] → tots els fitxers de assets/ són gestionats.
    • missing_import_mode: strict (dev) / warn (prod): en dev, un import no resolt trencarà el build; en prod, només avisa.
    • config/packages/twig.yaml: file_name_pattern: '*.twig'; a test, strict_variables: true.
    • Tailwind CSS es compila amb bin/console assets:tailwind:build (prod) o assets:tailwind:watch (dev); en desenvolupament l'AssetMapper serveix els assets en viu amb hot-reload (no cal carpeta assets_build/ fins a la primera build de producció).

    Custòdia d'arxius (Flysystem)¶

    config/packages/flysystem.yaml defineix un únic storage:

    flysystem:
    storages:
        item_document.storage:
            adapter: 'local'
            options:
                directory: '%kernel.project_dir%/var/data/registrals_storage'
    • Fora de l'arrel web (var/): impossible servir-lo per URL directa.
    • L'únic camí de lliurament és el controlador MediaController (guàrdia ItemVoter + StreamedResponse).
    • Les claus de storage segueixen el patró {uuid-item}/{uuid-document}.{ext} (gestió a src/Service/Storage/).
