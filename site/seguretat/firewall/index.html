    Tallafoc (firewall)¶

    Documentació del tallafoc de seguretat de Registrals, definit a config/packages/security.yaml. L'aplicació utilitza un únic tallafoc actiu (main, en mode lazy) més una excepció de dev/profiler.

    Com regenerar: bin/console debug:firewall i la lectura de config/packages/security.yaml.

    Definició general¶

    security:
    password_hashers:
        # Contrasenyes amb algoritme 'auto' (bcrypt/argon2 segons la plataforma)
        Symfony\Component\Security\Core\User\PasswordAuthenticatedUserInterface: 'auto'

    providers:
        app_user_provider:
            entity:
                class: App\Entity\User
                property: email          # l'usuari es carrega per correu electrònic

    firewalls:
        dev:                              # només dev: sense seguretat
            pattern: ^/(_profiler|_wdt|assets|build)/
            security: false
        main:                            # tallafoc principal
            lazy: true
            provider: app_user_provider
            user_checker: App\Security\UserChecker
            entry_point: form_login
            form_login:
                login_path: app_login
                check_path: app_login
                enable_csrf: true
                default_target_path: app_dashboard
                failure_handler: App\Security\LoginAuthenticationFailureHandler
            custom_authenticators:
                - App\Security\GoogleAuthenticator
            remember_me:
                secret: '%kernel.secret%'
                lifetime: 2592000        # 30 dies
                path: /
                always_remember_me: false
            logout:
                path: app_logout
                target: app_home

    lazy: true¶

    El tallafoc no carrega l'usuari ni la sessió a cada petició; ho fa només quan una autorització (controlador amb #[IsGranted], voter, o access_control) ho demana. Aquest és el comportament per defecte recomanat per Symfony 7 per a rendiment.

    UserChecker¶

    App\Security\UserChecker (src/Security/UserChecker.php) aplica dues verificacions:

    Mètode Quan Comportament
    checkPreAuth() Abans de l'autenticació Si l'usuari no és actiu (isActive() === false), llança CustomUserMessageAccountStatusException amb el missatge "El teu compte d'usuari ha estat suspès o desactivat per l'administració." + el motiu de bloqueig (si n'hi ha).
    checkPostAuth() Després de l'autenticació Si l'usuari té proveïdor local i el correu no està verificat, llança CustomUserMessageAccountStatusException amb "Cal verificar la teva adreça de correu electrònic amb el codi de 6 dígits abans d'accedir."

    Aquesta és la barrera que impedeix l'accés a comptes no verificats o suspesos; el Backoffice l'activa/desactiva amb app_admin_user_toggle_status.

    Form login (contrasenya)¶

    • login_path / check_path: app_login (/login), amb ANY (GET per mostrar el formulari, POST per enviar-lo).
    • enable_csrf: true: el formulari inclou un token CSRF (galeta _auth_csrf_*).
    • default_target_path: app_dashboard (/app/dashboard) — el destí per defecte després del login correcte.
    • failure_handler: App\Security\LoginAuthenticationFailureHandler (vegeu a sota).

    LoginAuthenticationFailureHandler¶

    App\Security\LoginAuthenticationFailureHandler (src/Security/LoginAuthenticationFailureHandler.php) hereda de DefaultAuthenticationFailureHandler i intercepta dues exceptions de repte abans del comportament estàndard:

    Excepció Què passa Destí
    PendingEmailVerificationException L'usuari existeix però el correu no està verificat. Es genera un OTP de 6 dígits (EmailOtpService, propòsit REGISTRATION_VERIFY) i es redirigeix al repte de verificació. /register/verify-email
    PendingTwoFactorAuthenticationException L'usuari té el 2FA activat. Es genera un OTP de 6 dígits (propòsit LOGIN_2FA) i es redirigeix al repte de 2FA. /login/2fa
    Qualsevol altra (contrasenya incorrecta, usuari no trobat…) Comportament estàndard de Symfony (flash d'error + redirecció al login). /login

    Reptes de seguretat (OTP)¶

    El mecanisme intern el proporciona App\Service\Security\EmailOtpService + App\Service\Security\AuthChallengeStorage:

    • Generació: codi de 6 dígits aleatori, signat amb HMAC (kernel.secret) per impedir manipulació.
    • Emmagatzematge: a la sessió (AuthChallengeStorage) amb el propòsit i el rememberMe original.
    • Cooldown: el repte de verificació de registre respecta un cooldown (per exemple, 60 s) entre reenviats; el 2FA no el respecta (permet reenviar-lo immediatament).
    • TTL: l'OTP expira en un temps curt (habitualment 5-10 minuts) i es invalida després de N intents fallits.
    • Verificació: el controlador SecurityChallengeController comprova l'OTP i, en cas d'èxit, completa l'autenticació (marca el correu verificat o activa el 2FA).

    El detall complet del servei d'OTP i dels cicles de vida dels reptes és al Bloc 2 → Controladors de seguretat.

    Google OAuth (custom authenticator)¶

    App\Security\GoogleAuthenticator (src/Security/GoogleAuthenticator.php) és un custom authenticator que s'activa només a la ruta connect_google_check:

    • supports(Request): retorna true només si _route === 'connect_google_check'.
    • authenticate(Request):
    • Valida el state (anti-CSRF) contra la sessió (oauth2state).
    • Obté el code de l'URL i canvia el token d'accés (OAuth2 authorization_code).
    • Obté el GoogleUser (correu + nom + cognoms + sub).
    • Construeix un UserBadge amb un callback que:
      • Si l'usuari ja existeix (per correu) i té proveïdor local sense providerId, el converteix a google (marca el correu verificat i neteja l'OTP).
      • Si no existeix, el crea amb el Pla Free per defecte (correu verificat).
    • Retorna un SelfValidatingPassport amb RememberMeBadge.
    • onAuthenticationSuccess(): redirigeix segons l'estat de l'usuari:
    • ROLE_ADMIN → app_admin_dashboard.
    • intended_plan === 'plus' a la sessió → Legal Gate (si cal) o app_plan.
    • No onboarding completat → app_onboarding_welcome.
    • Sinó → app_dashboard.
    • onAuthenticationFailure(): flash d'error + redirecció a app_login.

    El detall del flux OAuth2 (state, redirect_uri, scopes) és a Rutes → OAuth2 de Google.

    Remember me¶

    • secret: %kernel.secret% (el secret del nucli).
    • lifetime: 2592000 s (30 dies).
    • path: / (totes les rutes).
    • always_remember_me: false (el check _remember_me del formulari decideix).

    L'usuari pot eliminar el remember-me del dispositiu actual a /login/forget-device (rute app_login_forget_device).

    Logout¶

    • path: app_logout (/logout, ANY).
    • target: app_home (/) — el destí després del tancament.

    Matriz de rutes i tallafoc¶

    Ruta Tallafoc que l'aplica
    /_profiler, /_wdt, /assets, /build (només dev) dev (sense seguretat)
    Qualsevol altra ruta main (lazy)

    Seqüència de login amb contrasenya (diagrama)¶

    sequenceDiagram
  participant B as Navegador
  participant FW as Tallafoc main
  participant U as UserChecker
  participant FH as LoginAuthenticationFailureHandler
  participant O as EmailOtpService

  B->>FW: POST /login (email + contrasenya + _remember_me + CSRF)
  FW->>U: checkPreAuth (compte actiu?)
  alt Compte actiu
    U-->>FW: OK
    FW->>FW: Autentica (contrasenya correcta?)
    alt Contrasenya correcta
      FW->>U: checkPostAuth (correu verificat?)
      alt Correu verificat
        U-->>FW: OK
        FW-->>B: 302 → app_dashboard (o intended_target)
      else Correu no verificat (local)
        U-->>FW: PendingEmailVerificationException
        FW->>FH: onAuthenticationFailure
        FH->>O: issueOtp(REGISTRATION_VERIFY, respectCooldown=true)
        O-->>B: Correu amb OTP de 6 dígits
        FH-->>B: 302 → /register/verify-email
      else 2FA activat
        U-->>FW: PendingTwoFactorAuthenticationException
        FW->>FH: onAuthenticationFailure
        FH->>O: issueOtp(LOGIN_2FA, respectCooldown=false)
        O-->>B: Correu amb OTP de 6 dígits
        FH-->>B: 302 → /login/2fa
      end
    else Contrasenya incorrecta
      FW->>FH: onAuthenticationFailure (AuthenticationException)
      FH-->>B: Flash error → /login
    end
  else Compte no actiu
    U-->>FW: CustomUserMessageAccountStatusException (suspès)
    FW-->>B: Flash error → /login
  end
