    Voters¶

    Documentació del control d'accés objecte-a-objecte a Registrals. L'aplicació utilitza un únic voter (ItemVoter) per a la gestió de béns; les autoritzacions de certificat, traspàs i herència es fan al controlador o servei mitjançant les mateixes guàrdies (propietari + estat).

    Font: src/Security/Voter/ItemVoter.php.

    Què és un voter¶

    Un voter és una classe que respon a la pregunta "pot aquest usuari fer aquesta acció sobre aquest objecte?". S'usa amb el Security de Symfony:

    use Symfony\Bundle\SecurityBundle\Security;
use App\Security\Voter\ItemVoter;

public function show(Request $request, Item $item): Response
{
    $this->denyAccessUnlessGranted(ItemVoter::VIEW, $item); // llança AccessDeniedException si no pot
    // ...
}

    ItemVoter (control d'accés de béns)¶

    App\Security\Voter\ItemVoter (src/Security/Voter/ItemVoter.php) gestiona 5 atributs sobre l'entitat Item:

    Atribut Constant Què autoritza
    Veure ItemVoter::VIEW Consultar la fitxa del bé (incloent-hi congelats en mode lectura).
    Editar ItemVoter::EDIT Modificar el bé (afegir/eliminar documents, canviar la foto principal, etc.).
    Eliminar ItemVoter::DELETE Donar de baixa / eliminar el bé.
    Traspassar ItemVoter::TRANSFER Iniciar un traspàs C2C del bé.
    Certificar ItemVoter::CERTIFY Emetre un certificat digital del bé.

    Mètode supports()¶

    El voter només s'activa per a aquests 5 atributs i quan el subjecte és una instància d'Item:

    protected function supports(string $attribute, mixed $subject): bool
{
    return in_array($attribute, [self::VIEW, self::EDIT, self::DELETE, self::TRANSFER, self::CERTIFY], true)
        && $subject instanceof Item;
}

    Mètode voteOnAttribute()¶

    La lògica de votació:

    1. Si l'usuari no és un User autenticat → false (denegat).
    2. Si l'usuari té ROLE_ADMIN → true (l'administrador té accés complet de gestió).
    3. Sinó, es delega a les guàrdies privades segons l'atribut:
    Atribut Guardia Regla
    VIEW canView() El propietari sempre pot consultar el seu bé (fins i tot congelat en mode lectura).
    CERTIFY canCertify() Només el propietari i el bé ha d'estar en estat ACTIVE (mai congelats ni en traspàs).
    EDIT, DELETE canEditOrDelete() Només el propietari i el bé no ha d'estar en estats TRANSFER_PENDING, TRANSFERRED o FROZEN.
    TRANSFER canTransfer() Només el propietari i el bé ha d'estar en estat ACTIVE.

    Regles de disseny¶

    1. Propietari + estat: totes les guàrdies combinen la propietat ($item->getOwner()->getId() === $user->getId()) amb l'estat del bé (ItemStatus). Això impedeix, per exemple, editar un bé en traspàs o certificar un bé congelat.
    2. ROLE_ADMIN passa per dalt: l'administrador pot fer qualsevol acció sobre qualsevol bé (per a suport i moderació). El Backoffice l'explota a AdminItemController::updateStatus (canvis d'estat administratius).
    3. No hi ha delegació: un usuari no pot delegar el seu bé a un altre usuari (només a través d'un traspàs C2C, que canvia el propietari).

    On s'usa el voter¶

    Controlador / Servici Atributs usats Finalitat
    ItemController VIEW, EDIT, DELETE Fitxa del bé, alta, documents, baixa.
    CertificateController CERTIFY Emissió de certificats.
    TransferController TRANSFER Inici de traspàs.
    MediaController VIEW Lliurament privat de documents (guàrdia + StreamedResponse).
    MobileHandoffController VIEW, EDIT Handoff mòbil (captura i pujada de fotos).
    AdminItemController EDIT (implícit via ROLE_ADMIN) Canvis d'estat administratius.

    Nota: les accions sobre certificats (UserCertificateController) i traspassos (TransferController) també fan servir el voter, però el control d'estat addicional (per exemple, "només es pot certificar un bé actiu") el fa el servei de domini (CertificateIssuerService, TransferService) per a coherència de negoci. El voter és la primera barrera; el servei és la segona.

    Com afegir un voter nou (recepta)¶

    1. Crea la classe a src/Security/Voter/ (per exemple, CertificateVoter.php).
    2. Defineix els atributs (constants VIEW, EDIT, …) i el mètode supports() (només per a l'entitat corresponent).
    3. Implementa voteOnAttribute() amb les guàrdies de negoci (propietari, estat, pla).
    4. Registra'l (no cal fer res: l'autoconfigure el detecta com a voter).
    5. Usa'l al controlador amb $this->denyAccessUnlessGranted(...).

    Regla: no duplicar la lògica de negoci entre el voter i el servei; el voter ha de ser fi (només permisos) i el servei ample (validació de negoci + efectes). Si cal, el servei pot cridar el voter per reutilitzar la lògica.

    Relació amb el tallafoc¶

    Nivell Què resol On
    Tallafoc (access_control) Quina ruta pot accedir un rol config/packages/security.yaml
    Legal Gate Acceptació de clàusules a /app/* LegalGateSubscriber
    Voter Quina acció sobre quin objecte src/Security/Voter/
    Servei de domini Validació de negoci + efectes src/Service/

    El voter no substitueix el tallafoc: una ruta /app/* pot estar protegida per ROLE_USER al tallafoc, però un bé concret pot ser denegat pel voter si l'usuari no n'és el propietari.
