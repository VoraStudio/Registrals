    Rutes: pàgines públiques i autenticació¶

    Mapa de les rutes públiques de la plataforma (landing, blog, contacte, manual…) i del flux complet d'autenticació: registre, verificació de correu, login amb contrasenya, 2FA per correu, recuperació de contrasenya, OAuth2 de Google i onboarding.

    Font: bin/console debug:router (nucli del 17/11/2026). 29 rutes en aquest fitxer.

    Pàgines públiques (PageController)¶

    11 rutes d'informació pública (totes GET,HEAD):

    Ruta Path Mètode Descripció
    app_home / home Landing corporativa (hero, valors, CTA).
    app_producte /producte producte Fitxa del producte i el model Freemium.
    app_legal /legal legal Política de privadesa i termes (text públic).
    app_legal_ai_sovereign /legal/ia-sobirana aiTransparency Transparència de l'assistència IA sobirana (AI Act).
    app_holding /properament holding Pàgina "Properament" (Pla Unlimited, etc.).
    app_about /sobre-nosaltres about Sobre Vora Data & Studio.
    app_histories /histories histories Histories i casos.
    app_press /premsa press Nota de premsa.
    app_contact /contacte contact Formulari de contacte.
    app_manual /manual manual Manual d'usuari (pàgina pública).
    app_help /ajuda manual Ajuda (alias del manual).

    Blog (BlogController)¶

    Ruta Path Mètode Descripció
    app_blog /blog index Llista d'articles (Markdown a content/blog/).
    app_blog_show /blog/{slug} show Article individual.
    app_blog_translate /api/blog/translate translate POST — API interna de traducció prèvia (memòria cau per hash SHA-256; vegeu Webhooks i API).

    Els articles del blog pretradueixen-se a ES/EN amb la comanda app:blog:pretranslate.

    Registre de compte (RegistrationController + SecurityChallengeController)¶

    Ruta Path Mètode Descripció
    app_register /register register Formulari d'alta (nom, cognoms, correu, contrasenya). Crea l'usuari amb emailVerified=false.
    app_register_verify_email /register/verify-email verifyRegistrationEmail GET,POST — Repte del codi OTP de 6 dígits enviat per correu.
    app_register_verify_email_resend /register/verify-email/resend resendRegistrationEmail POST — Reenvia el codi (amb cooldown).
    app_register_verify_cancel /register/verify-email/cancel cancelRegistrationVerify GET — Cancel·la el registre i elimina l'usuari pendent.

    Inici de sessió (SecurityController)¶

    Ruta Path Mètode Descripció
    app_login /login login ANY — Formulari de login (contrasenya + opció Google).
    app_login_forget_device /login/forget-device forgetDevice GET,POST — Elimina el remember-me del dispositiu actual.
    app_logout /logout logout ANY — Tancament de sessió (redirigeix a app_home).

    2FA per correu en login (SecurityChallengeController)¶

    Ruta Path Mètode Descripció
    app_login_2fa /login/2fa verifyLoginTwoFactor GET,POST — Verificació del segon factor (codi de 6 dígits).
    app_login_2fa_resend /login/2fa/resend resendLoginTwoFactor POST — Reenvia el codi.
    app_login_2fa_cancel /login/2fa/cancel cancelLoginTwoFactor GET — Cancel·la el 2FA i torna al login.

    El 2FA es genera quan l'usuari ho té activat (repte LOGIN_2FA); el detall del tallafoc i del failure handler que redirigeix a aquestes rutes és a Tallafoc (firewall).

    Recuperació de contrasenya (ResetPasswordController)¶

    Ruta Path Mètode Descripció
    app_forgot_password /forgot-password request GET,POST — Sol·licitud del token de recuperació (enviament per correu).
    app_reset_password /reset-password/{token} reset GET,POST — Canvi de contrasenya amb token (SHA-256 + expiració).

    OAuth2 de Google (GoogleOAuthController + GoogleAuthenticator)¶

    Ruta Path Mètode Descripció
    connect_google_start /connect/google connect ANY — Inicia el flux OAuth2 (redirigeix a Google amb state anti-CSRF a la sessió).
    connect_google_check /connect/google/check connectCheck ANY — Callback de Google; autenticat per GoogleAuthenticator (custom authenticator).

    Comportament del GoogleAuthenticator (vegeu Tallafoc):

    • Valida state + code; obté el correu de Google.
    • Si l'usuari ja existeix (per correu) amb proveïdor local sense providerId, el converteix a google (marca el correu verificat i neteja l'OTP).
    • Si no existeix, el crea amb el Pla Free per defecte (correu verificat) i l'autentica.
    • Després de l'èxit:
    • Si té ROLE_ADMIN → app_admin_dashboard.
    • Si intended_plan === 'plus' a la sessió → Legal Gate (si cal) o app_plan.
    • Si no ha completat l'onboarding → app_onboarding_welcome.
    • Sinó → app_dashboard.

    Onboarding (OnboardingController)¶

    Ruta Path Mètode Descripció
    app_onboarding_welcome /onboarding/welcome welcome ANY — Benvinguda i pas a pas inicial.
    app_onboarding_complete /onboarding/complete complete POST — Marca l'onboarding com a completat.

    Matriz d'accés (access_control)¶

    Totes les rutes d'aquest fitxer són PUBLIC_ACCESS (vegeu Rols i control d'accés):

    Patró de camí Rol
    ^/login, ^/register, ^/forgot-password, ^/reset-password, ^/connect PUBLIC_ACCESS
    ^/verify, ^/transfer, ^/llegat, ^/herencia PUBLIC_ACCESS (token/OTP dins del controlador)
    ^/api/track PUBLIC_ACCESS
    ^/webhook PUBLIC_ACCESS (validació de firma)
    ^/guia-destils PUBLIC_ACCESS
    (qualsevol altra ruta pública, p. ex. /, /producte, /blog, /legal, /contacte, /manual, /ajuda, /histories, /premsa, /sobre-nosaltres, /properament, /onboarding) PUBLIC_ACCESS implícit (no exigirà rol; l'accés real el garanteix el controlador o el Legal Gate)

    Nota: Symfony aplica només la primera regla coincident. Les rutes públiques sense regla explícita a access_control no tenen cap rol exigint; la seva seguretat rau a la lògica del controlador (no requereixen autenticació) i al Legal Gate (només a /app/*).

    Flux de login complet (seqüència)¶

    sequenceDiagram
  participant U as Usuari
  participant S as SecurityController
  participant FW as Tallafoc main
  participant CH as SecurityChallengeController
  participant O as EmailOtpService

  U->>S: POST /login (contrasenya + _remember_me)
  S->>FW: check_path (app_login)
  alt Contrasenya correcta i correu verificat
    FW-->>U: 302 → app_dashboard (o intended_target)
  else Correu no verificat (local)
    FW->>CH: PendingEmailVerificationException
    CH->>O: issueOtp(REGISTRATION_VERIFY)
    O-->>U: Correu amb codi de 6 dígits
    FW-->>U: 302 → /register/verify-email
  else 2FA activat
    FW->>CH: PendingTwoFactorAuthenticationException
    CH->>O: issueOtp(LOGIN_2FA)
    O-->>U: Correu amb codi de 6 dígits
    FW-->>U: 302 → /login/2fa
  else Contrasenya incorrecta
    FW-->>U: Flash error → /login
  end
